# Offline Azerbaijani editor: typed entities and quality review

Starting main revision: `c906454f0fe86ce7bfbca504bdbec52a4d6ef659`.

The included entity data is a finite, locally reviewed subset. `lib/editor/entities/sources.ts` pins the source labels. Geographic district and city names were checked against *Azərbaycanın regionları 2025* (https://www.stat.gov.az/menu/6/statistical_yearbooks/source/regions_2025.pdf). Capitalization categories follow the Azerbaijani orthography rules at https://frameworks.e-qanun.az/42/c_f_42073.html. This is not an exhaustive national registry. No runtime network access, hosted model, or AI API is used.

`NamedEntity` specifies kind, canonical spelling, capitalization policy, inflection policy, aliases, and provenance. The resolver indexes single-word inflections and typo signatures before requests. Ambiguous edit alternatives are rejected. Multiword names are protected before spelling; noun-case endings on official territorial and geographic names remain part of the protected spelling. The email signature uses the same personal-name lookup.

The entity fixture contains 1,560 examples: 432 existing reviewed cases plus 1,128 frozen generated cases from the curated inventory. Generation is reproducible with `node --import tsx scripts/generate-typed-entity-corpus.ts`; expected outputs do not call the editor. Its scenarios cover five grammatical cases, four typo operations, titles, surnames, and multiword names. Cases share grammatical frames, so the count measures variant coverage, not 1,560 independent writing styles. `docs/named-entity-holdout-results.json` contains per-category results and the frozen fixture SHA-256.

The separate `scripts/evaluate-unseen.ts` evaluation uses 200 newly authored sentences and two independently altered input surfaces for each, for 400 previously unseen inputs. The full expected text, actual output, pass/fail, and idempotency for each are in `docs/unseen-evaluation-results.json`. **306/400 matched exactly, 94/400 did not.** Most misses involve inflected words absent from the finite lexical index or multiple meanings of undiacritized tokens (for example *surəti* versus *sürəti*). This remains a measurable accuracy limitation of an offline dictionary-driven editor. The separate corpus was not used to silently change its expected answers.

`npm run benchmark:check` enforces warm p95 ceilings. A 5,000-word logical document is split into five production-safe chunks because requests accept at most 10,000 characters. Individual runs fluctuate; comparison should use the same Node version and machine. The GitHub workflow runs lint, typecheck, tests, dictionary reproduction, holdout reports, unseen evaluation, build, and benchmark. Its diagnostics are attached to the workflow run.
